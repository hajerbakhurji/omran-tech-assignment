# موقع مجموعة عمران تك — إعادة تصميم

إعادة تصوّر لموقع **مجموعة عمران تك** بأسلوب حديث، باللغتين العربية والإنجليزية.
هذا المشروع هو حلّي **للخيار الأول (موقع شركة هندسية)** في الاختبار العملي لوظيفة مطور ومصمم مواقع ويب.

- **العرض المباشر (Live Demo):** https://omran-tech-assignment.vercel.app
  - العربي: https://omran-tech-assignment.vercel.app/ar/index.html
  - الإنجليزي: https://omran-tech-assignment.vercel.app/en/index.html
  - **المساعد الذكي:** https://omran-tech-assignment.vercel.app/ar/ai.html
- **المستودع (Git Repository):** https://github.com/hajerbakhurji/omran-tech-assignment

الموقع منشور على **Vercel**، ويتحدّث تلقائيًا عند كل رفع على GitHub. توجد أيضًا نسخة على GitHub Pages (https://hajerbakhurji.github.io/omran-tech-assignment/)، لكن المساعد الذكي لا يعمل فيها لأن GitHub Pages لا يشغّل سيرفرات.

## نظرة سريعة

المطلوب في الاختبار كان Landing Page للصفحة الرئيسية. بنيت الصفحة الرئيسية كاملة، ثم وسّعت التصميم ليشمل باقي صفحات الموقع حتى تظهر الهوية بشكل متكامل:

| الصفحة | العربي | الإنجليزي |
|---|---|---|
| الصفحة الرئيسية (Landing Page) | `dist/ar/index.html` | `dist/en/index.html` |
| من نحن، الخدمات، المشاريع، الأخبار، المقالات، التواصل | ✓ | ✓ |
| ٨ صفحات خدمات و٥ صفحات أقسام | ✓ | ✓ |
| صفحة لكل مشروع (٣٧–٣٨ مشروع) | ✓ | ✓ |
| صفحة لكل خبر ومقالة | ✓ | ✓ |
| **صفحة المساعد الذكي** (محادثة حقيقية مع Claude) | ✓ | ✓ |

**المجموع: ١٤٢ صفحة.**

### أقسام الصفحة الرئيسية (بالترتيب)
1. **الواجهة (Hero):** عنوان واضح، ووصف مختصر للشركة، وزرّان («ابدأ مشروعك» و«استعرض مشاريعنا»)، وأرقام سريعة: سنة التأسيس، وعدد المشاريع، والأقسام، والمدن.
2. **شريط التقنيات:** الحديد البارد، الهولوكور، الخرسانة مسبقة الصب، BIM...
3. **المساعد الذكي:** قسم يعرّف بالمساعد، وينقل لصفحة المحادثة (انظر «المساعد الذكي» أدناه).
4. **الأقسام الخمسة:** الاستشارات، والمقاولات، والمصنع، والتشطيبات، والخدمات البيئية.
5. **الخدمات الثمانية.**
6. **طريقة العمل** في خمس خطوات.
7. **مشاريع مختارة.**
8. **لماذا الحديد البارد:** مع فيديو مراحل البناء من موقع الشركة.
9. **آراء العملاء.**
10. **شركاء النجاح** و**الشهادات** (تُكبَّر عند الضغط).
11. **آخر الأخبار.**
12. **دعوة للتواصل (CTA)** ثم الفوتر.

## التشغيل محليًا

**المتطلبات:** Python 3.8 أو أحدث. الموقع نفسه لا يحتاج أي مكتبات.

**لتشغيل المساعد الذكي محليًا (اختياري):** ثبّت المكتبة وضع مفتاح API كمتغير بيئة على جهازك:

```bash
pip install -r requirements.txt
```

ثم عرّف المتغير `ANTHROPIC_API_KEY` على جهازك (أو في إعدادات التشغيل في PyCharm). بدون المفتاح يعمل الموقع كاملًا، والمساعد يعرض رسالة «غير متاح».

```bash
python serve.py
```

يبني هذا الأمر الموقع ويفتح الصفحة العربية في المتصفح. للنسخة الإنجليزية:

```bash
python serve.py en
```

أوامر أخرى:

```bash
python build.py    # يبني الموقع فقط داخل مجلد dist
python check.py    # يفحص الصفحات بحثًا عن روابط أو صور مفقودة
```

**من PyCharm:** افتح المجلد كمشروع، واختر من القائمة أعلى اليمين **Run website** ثم اضغط ▶.

**بدون Python:** مجلد `dist` يحتوي الموقع جاهزًا، ويمكن رفعه مباشرة على أي استضافة.

## التقنيات المستخدمة ولماذا

| التقنية | الاستخدام |
|---|---|
| **HTML / CSS / JavaScript** (بدون أي Framework) | الموقع النهائي |
| **Python** (المكتبات الأساسية فقط) | سكربت صغير يولّد صفحات HTML من ملفات المحتوى |
| **Google Fonts** | خطوط Archivo و IBM Plex Sans و IBM Plex Sans Arabic |
| **Vercel** (خطة Hobby المجانية) | استضافة الموقع + دالة سيرفر (Serverless Function) للمساعد |
| **Claude API** (نموذج `claude-opus-5-5`) + مكتبة `anthropic` | «عقل» المساعد الذكي |

### لماذا موقع ثابت (Static) وليس WordPress أو React؟

- **السرعة:** صفحات HTML جاهزة، بدون قاعدة بيانات أو سيرفر يبني الصفحة عند كل زيارة. وملف JavaScript الوحيد حجمه حوالي ٨ كيلوبايت.
- **سهولة الاستضافة ومجانيتها:** يرفع على GitHub Pages أو Netlify أو أي استضافة بدون إعدادات.
- **الأمان:** لا توجد لوحة تحكم أو إضافات تحتاج تحديثات أمنية. الموقع الحالي مبني على WordPress مع عدد كبير من الإضافات.
- **محركات البحث (SEO):** كل صفحة HTML كاملة من البداية، مع عنوان ووصف لكل صفحة.
- **React أو Next.js غير ضروريين هنا:** الموقع تعريفي، ولا يحتاج حالة (state) معقدة أو تفاعل كثيف. استخدامهما يضيف أدوات بناء واعتماديات بدون فائدة حقيقية لهذا النوع من المواقع.

### لماذا سكربت Python لبناء الصفحات بدل كتابتها يدويًا؟
الموقع ١٤٠ صفحة بلغتين، وكل الصفحات تشترك في الهيدر والفوتر والتصميم. كتابتها يدويًا تعني تكرار نفس الكود ١٤٠ مرة، وأي تعديل يحتاج تغيير كل الصفحات. السكربت يأخذ المحتوى من `content.py` ومجلد `data/` ويركّبه في قالب واحد. والنتيجة صفحات HTML عادية تمامًا.

### لماذا CSS عادي وليس Tailwind أو Bootstrap؟
- التصميم مخصص بالكامل، ولا يعتمد على مكوّنات جاهزة.
- **دعم العربية (RTL):** استخدمت CSS Logical Properties مثل `margin-inline-start` بدل `margin-left`. بهذه الطريقة نفس ملف الـ CSS يعمل للعربي والإنجليزي، ويكفي تغيير `dir="rtl"` لينقلب التصميم كاملًا.
- الألوان والمسافات معرّفة كمتغيرات (CSS Variables) في أعلى الملف، فتغيير الهوية يحتاج تعديل سطور قليلة.

## المساعد الذكي

صفحة محادثة حقيقية (`ai.html`) يسأل فيها الزائر عن خدمات الشركة ومشاريعها والبناء بالحديد البارد، بالعربي أو الإنجليزي.

### كيف يعمل
```
المتصفح (ai.html + main.js)  →  /api/chat (سيرفر على Vercel، المفتاح عنده)  →  Claude API  →  الرد يرجع للمتصفح
```

- **ليش سيرفر؟** الاتصال بـ Claude يحتاج مفتاح API مرتبط بالحساب والدفع. لو وُضع في JavaScript، يستطيع أي زائر رؤيته من «View Source» واستخدامه. لذلك المتصفح يرسل السؤال لسيرفرنا (`api/chat.py`)، والسيرفر وحده يعرف المفتاح (محفوظ كمتغير بيئة في Vercel، وليس في الكود).
- **معلومات الشركة:** الملف `api/knowledge.md` يحتوي معلومات الشركة (الأقسام، الخدمات، المشاريع، الفروع، التواصل)، مأخوذة من محتوى الموقع نفسه. يُرسل مع كل سؤال كتعليمات ثابتة (System Prompt). المحتوى صغير (~٣٤ ألف حرف)، فلا حاجة لقاعدة بيانات أو بحث (RAG).
- **قواعد المساعد:** يجيب فقط من معلومات الشركة، لا يخترع أسعارًا أو مواعيد (يوجّه لصفحة التواصل)، يرفض المواضيع الخارجية بلطف، ويرد بلغة السائل.
- **التكلفة:** معلومات الشركة لا تتغير، فتُخزَّن مؤقتًا (Prompt Caching) وتصبح أرخص بكثير بعد أول سؤال. كل سؤال يكلّف تقريبًا سنتًا إلى سنتين.

### الحماية
- السؤال لا يتجاوز ٥٠٠ حرف، والمحادثة لا تتجاوز ١٠ أسئلة (يتحقق منها السيرفر، وليس المتصفح فقط).
- السيرفر يتحقق من شكل المحادثة قبل إرسالها (الأدوار والترتيب).
- حد أعلى للصرف الشهري في حساب Anthropic.
- الرد يُعرض كنص (`textContent`) وليس HTML، فلا يمكن حقن كود في الصفحة.
- عند أي خطأ (مشغول، غير متاح، رفض) تظهر رسالة واضحة بلغة الزائر بدل خطأ تقني.
- خيار «Fallback»: لو رفض النموذج سؤالًا لأسباب أمان، تعيد الـ API المحاولة تلقائيًا على نموذج بديل.

## هيكل المشروع

```
assets/      styles.css (التصميم) و main.js (التفاعل)
media/       الصور والفيديو
data/        projects.json و posts.json و pages.json
content.py   نصوص الموقع باللغتين والإعدادات
build.py     يبني صفحات الموقع داخل dist/
serve.py     يبني الموقع ويشغّله ويفتحه في المتصفح
check.py     يفحص الروابط والصور
api/         chat.py (سيرفر المساعد) و knowledge.md (معلومات الشركة للمساعد)
requirements.txt   مكتبة anthropic (للسيرفر فقط)
vercel.json  إعدادات Vercel: أمر البناء، ومجلد النشر، وإعدادات دالة السيرفر
.github/     النشر التلقائي على GitHub Pages
dist/        الموقع النهائي (يُولَّد تلقائيًا ولا يُعدَّل يدويًا)
```

**طريقة عمل `build.py` باختصار:** لكل لغة يمرّ على كل صفحة، ويستدعي الدالة الخاصة بها (`home_page` و `project_page` و `contact_page`...). كل دالة ترجع HTML، ثم توضع داخل القالب العام `layout` (الهيدر والفوتر). الكلاس `Page` يحفظ لغة الصفحة ومسارها، ويحسب الروابط النسبية.

## أبرز القرارات التصميمية

- **الأسلوب: «صناعي جريء» (Bold Industrial).** خلفيات داكنة بدرجات الفحم والحديد تعكس طبيعة البناء والحديد البارد، مع صور مشاريع كبيرة.
- **الألوان:** اللون الأحمر من شعار عمران تك هو لون التمييز الوحيد، ويُستخدم للأزرار والعناصر المهمة فقط. والأقسام تتناوب بين الداكن والفاتح حتى لا تصبح الصفحة متعبة.
- **الخطوط:** Archivo بعرض ضيق للعناوين الإنجليزية لإحساس هندسي قوي، و IBM Plex Sans Arabic للعربي لأنه واضح ومتناسق مع Plex الإنجليزي.
- **الدعوة للتواصل (CTA):** زر «ابدأ مشروعك» يظهر في الهيدر والواجهة وقبل الفوتر، مع زر اتصال عائم على الجوال، فالزائر لا يحتاج أبدًا البحث عن طريقة التواصل.
- **ترتيب المحتوى:** من «من نحن وماذا نقدّم» إلى «كيف نعمل» ثم «الدليل» (المشاريع وآراء العملاء والشهادات) وأخيرًا «تواصل معنا».
- **التجاوب (Responsive):** قائمة جوال بملء الشاشة، والشبكات تتحول من ٤ أعمدة إلى ٢ ثم ١ حسب عرض الشاشة.
- **إمكانية الوصول (Accessibility):** رابط «تخطَّ إلى المحتوى»، وإطار واضح عند التنقل بلوحة المفاتيح، ونصوص بديلة للصور، وتبويبات التواصل تعمل بالأسهم، واحترام إعداد «تقليل الحركة» في الجهاز.

## أبرز القرارات التقنية

- **نقل المحتوى:** الموقع الحالي مبني على WordPress، فسحبت المحتوى باللغتين من واجهة WordPress REST API بدل نسخه يدويًا، ثم ربطت كل صفحة إنجليزية بنسختها العربية.
- **تنظيف المحتوى:** أزلت نصوصًا دخيلة كانت تظهر داخل وصف المشاريع في الموقع القديم (روابط «المشروع السابق/التالي» و«جميع المشاريع»)، وحوّلت معلومات المشروع (الموقع والمساحة والتكلفة والتاريخ) إلى جدول «تفاصيل المشروع».
- **الصور محلية:** نزّلت كل الصور والفيديو (٣٤٤ ملف، حوالي ١١٠ ميجا) بأسماء واضحة، حتى لا يعتمد الموقع على السيرفر القديم.
- **الأداء:** الصور تُحمَّل عند الحاجة (`loading="lazy"`)، والفيديو لا يعمل إلا عندما يظهر على الشاشة.
- **فلترة المشاريع:** بـ JavaScript بسيط بدون إعادة تحميل الصفحة، ورابط الفلتر قابل للمشاركة (مثل `projects.html#fuel`).
- **نماذج التواصل:** أربعة نماذج مثل الموقع الحالي. لعدم وجود سيرفر، الإرسال يفتح تطبيق البريد لدى الزائر مع تعبئة البيانات تلقائيًا.

## استخدام أدوات الذكاء الاصطناعي

حسب تعليمات الاختبار، هذا إفصاح كامل عن استخدام الذكاء الاصطناعي في المشروع.

**الأداة:** Claude Code من شركة Anthropic، داخل تطبيق Claude لسطح المكتب.

**دوري أنا:**
- اختيار الخيار الأول (موقع شركة هندسية) ونطاق العمل: الموقع كامل بدل صفحة واحدة.
- اختيار الاتجاه التصميمي: «صناعي جريء».
- قرار دعم اللغتين العربية والإنجليزية.
- طلب إضافة المساعد الذكي، ثم قرار أن يكون مساعدًا يعمل فعليًا (وليس صفحة تعريفية فقط).
- إنشاء حساب Anthropic وشحن الرصيد ووضع حد للصرف، وإنشاء مشروع Vercel وإضافة مفتاح API بنفسي.
- طلب تنزيل الصور محليًا.
- طلب تبسيط الكود ليكون مقروءًا وسهل الصيانة.
- مراجعة النتائج وطلب التعديلات.

**ما نفّذه Claude Code بتوجيهي:**
- سحب المحتوى من واجهة WordPress API وتنظيفه وربط النسختين العربية والإنجليزية.
- تصميم الهوية البصرية وكتابة كامل الـ CSS.
- كتابة `build.py` و `main.js` و `serve.py` و `check.py`.
- كتابة سيرفر المساعد (`api/chat.py`) وتعليماته، وتوليد `api/knowledge.md` من محتوى الموقع، وإعداد `vercel.json`.
- صياغة بعض النصوص: اختصار وتنقيح النصوص الإنجليزية، ونصوص قسم المساعد الذكي.
- ترجمة صفحة الخدمات البيئية (ESSCO) إلى العربية، لأنها كانت بالإنجليزية فقط في الموقع الحالي.
- اختبار الموقع في المتصفح على مقاسات مختلفة، وإصلاح المشاكل التي ظهرت.

**داخل المنتج نفسه:** المساعد الذكي في الموقع يستخدم **Claude API** (نموذج `claude-opus-5-5`) للإجابة على أسئلة الزوار.

**الخلاصة:** معظم الكود مكتوب بواسطة Claude Code، والقرارات والتوجيه والمراجعة مني. راجعت الكود وفهمته، وأستطيع شرح أي جزء منه وتعديله.

## الاختبار

- `check.py`: فحص الصفحات ١٤٢ كلها، بدون روابط أو صور مفقودة.
- **المساعد الذكي** على الموقع المنشور:
  - سؤال بالعربي عن الحديد البارد: إجابة صحيحة من معلومات الشركة خلال ~٥ ثوانٍ.
  - سؤال بالإنجليزي عن سعر فيلا: لم يخترع سعرًا، ووجّه لنموذج التواصل وأرقام الهاتف.
  - سؤال خارج الموضوع: اعتذر بلطف وأعاد الحديث لخدمات الشركة.
- **سيرفر المساعد بدون مفتاح:** تجربة الحالات الخاطئة (سؤال طويل، أكثر من ١٠ أسئلة، ترتيب خاطئ) وكلها رُفضت برسالة مناسبة.
- اختبار يدوي في المتصفح باللغتين على:
  - كمبيوتر: 1366px
  - تابلت أفقي: 1024px
  - تابلت عمودي: 768px
  - جوال: 375px
- في كل المقاسات: لا يوجد تمرير أفقي، والهيدر يتسع، والقائمة تتحول لزر قائمة على الشاشات الأصغر من 1080px.
- اختبار: فلترة المشاريع، وتبويبات التواصل، وعارض الصور، وقائمة الجوال، وتبديل اللغة.

## قيود معروفة وتطويرات مستقبلية

- **نماذج التواصل** تفتح تطبيق البريد لدى الزائر. للإرسال المباشر، يمكن ربطها بخدمة مثل Formspree أو بنظام CRM الشركة.
- **حد الأسئلة في المساعد** لكل محادثة، وليس لكل زائر. زائر مصرّ يستطيع بدء محادثات جديدة، لذلك الحماية الأساسية من الصرف الزائد هي الحد الأعلى في حساب Anthropic. للإنتاج الفعلي يمكن إضافة حد لكل عنوان IP (مثلًا عبر Vercel Firewall أو Upstash).
- **المساعد لا يحفظ المحادثات** ولا يعرض الرد كلمة بكلمة (Streaming)؛ الرد يظهر كاملًا بعد ثوانٍ مع مؤشر «يكتب».
- **محتوى غير مترجم في الموقع الأصلي:** مشروع «محطة وقود الدريس» موجود بالإنجليزية فقط، ومقالة «الخدمات الهندسية العامة» موجودة بالعربية فقط، فبقي كل منهما بلغته.
- **صورة المعاينة عند المشاركة (og:image):** تحتاج رابطًا كاملًا بعد تحديد الدومين النهائي.
